# ADR-002: 見出し構造ベースのチャンク分割を採用する

- Status: Accepted
- Date: 2026-07

## Context

チャンク分割には主に3方式がある。

| 方式 | 概要 | 弱点 |
|---|---|---|
| 固定長分割 | Nトークンごとに機械的に切る | 文・セクションの途中で切れ、意味が壊れる |
| 見出し構造ベース | Markdownのh2/h3単位で切る | セクション長のばらつき |
| セマンティック分割 | embedding類似度で意味の切れ目を検出 | 実装コスト・処理コスト高 |

## Decision

見出し構造ベースを主軸とし、長すぎるセクション(500トークン超)のみ段落境界で二次分割+100トークンのオーバーラップを付与する。

## Rationale

1. **コーパスの性質**: 社内マニュアル・FAQは見出しが「1トピック=1回答単位」として整備されており、見出し単位がそのまま理想の検索単位になる
2. **引用元の提示**: FR-04(引用元明示)のため、`文書名 > セクション`という人間が理解できる単位でチャンクが切れている必要がある。固定長分割だと「◯◯マニュアルの1024〜1536トークン目」のような無意味な引用になる
3. **コンテキスト付与**: 各チャンク先頭に「文書タイトル + セクションパス」を付与してからembedding化する。「当日キャンセル」というセクションが複数文書にある場合の曖昧性を解消するため

## Consequences

- (+) 引用UXが良い、実装がシンプル、評価ハーネスの正解チャンク指定(document+section)が安定する
- (−) 見出しのない文書には弱い → 取り込み時に警告し、固定長へフォールバック
- 分割ロジックは純粋関数(ChunkSplitter)として切り出し、単体テストで境界ケース(空セクション、巨大セクション、ネスト見出し)を担保する
