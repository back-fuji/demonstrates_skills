# ADR-001: ベクトルストアにpgvector(PostgreSQL拡張)を採用する

- Status: Accepted
- Date: 2026-07

## Context

RAGのベクトル検索基盤として、専用ベクトルDB(Pinecone / Qdrant / Weaviate)とPostgreSQL拡張のpgvectorが候補になる。

## Decision

pgvectorを採用する。

## Rationale

1. **規模が小さい**: チャンク数は当面600件、成長しても数万件。専用DBの性能優位が意味を持つのは数百万ベクトル以上の領域
2. **運用コンポーネントを増やさない**: 文書メタデータ・チャンク・検索ログとベクトルが同一DBにあれば、JOINひとつで「is_activeなチャンクのみ検索」のようなフィルタが書け、整合性管理(文書削除時のベクトル同期など)が不要になる
3. **トランザクション**: 取り込みジョブで「チャンク+embeddingを原子的に保存」できる。外部ベクトルDBだと2フェーズの整合性問題が生じる
4. **コスト**: 追加インフラゼロ。クリニック規模の社内ツールという想定顧客に対して過剰設計を避ける

## Consequences

- (+) インフラ構成がシンプル、RDS1台で完結
- (−) 数百万ベクトル規模ではスケール限界が来る → その際はRead Replica、次いで専用DB移行を検討(移行境界としてEmbeddingClient/検索クエリをRepository層に隔離済み)
- 検索性能はインデックス選定に依存 → ADR-003で計測して判断
